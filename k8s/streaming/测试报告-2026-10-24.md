# Kafka, AutoMQ and Pulsar K3s Test Report

## Scope

- Date: 2026-10-24
- Cluster: existing five-node K3s cluster on the LAN Proxmox environment.
- Namespace: `streaming-mq-test`.
- Systems: Apache Kafka 3.9.2, AutoMQ 1.5.5 with MinIO, and Apache Pulsar
  3.3.9 standalone.
- Test contract: each independent client Job creates its topic, produces 10
  messages, consumes 10 messages, and exits nonzero on a count mismatch.

## Corrections Verified During The Drill

- Bucket initialization is a separate Job applied only after MinIO's rollout
  completes, preventing the initial connection race.
- Kafka's ConfigMap is mounted below `/opt/kafka/config/custom`; the official
  image reserves `/etc/kafka/secrets` as read-only.
- The Kafka and AutoMQ Services expose both 9092 and KRaft controller port
  9093, with `publishNotReadyAddresses: true` so a one-node controller can
  self-register before the broker readiness probe succeeds.
- Pulsar clients use `--url pulsar://pulsar:6650`; the test producer sends all
  ten messages in one CLI process using repeated `-m` parameters.
- Test Pods have fixed node selectors to reuse pulled images and avoid
  scheduling onto nodes whose existing workloads lack sufficient requested
  CPU or memory.

## Environment Retention

The namespace, completed Jobs, live broker Pods, MinIO data, and downloaded
images are intentionally retained. `run-k3s-test.sh` exits without changes if
the namespace exists. To recreate the isolated test environment deliberately:

```bash
cd k8s/streaming
RESET=true bash run-k3s-test.sh
```

This is a single-node functional fixture, not a production topology. Kafka and
Pulsar use `emptyDir`; AutoMQ uses an embedded MinIO backend solely for the
test.
