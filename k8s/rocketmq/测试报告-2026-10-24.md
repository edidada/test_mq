`127.0.0.1:9876` 配置，实际连接 Kubernetes Service `rocketmq-namesrv:9876`。

## 保留现场

脚本默认不删除命名空间。当前保留 NameServer、Broker、Service、Java Job 日志和节点
镜像缓存，便于手动继续测试：

```bash
ssh k3s-master 'kubectl get deploy,svc,pods,jobs -n rocketmq-resilience-test'
ssh k3s-master 'kubectl logs job/rocketmq-java-e2e -n rocketmq-resilience-test'
```

从头重跑使用 `RESET=true bash ./run-k3s-test.sh`；不再需要时才执行：

```bash
kubectl delete namespace rocketmq-resilience-test
```

该 Java 示例验证 RocketMQ 的生产与消费，不包含 MySQL 持久化逻辑，因此未声称覆盖
MySQL 故障恢复或生产级 Broker 持久化配置。
