# 共享中间件迁移与回归测试报告（2026-10-25）

## 结论

通过。在不新增 VM、且避免重复占用 K3s 节点资源的前提下，测试 namespace 中的
长期中间件已迁移或切换到 `middleware`：

- `rocketmq-resilience-test` 不再部署 NameServer 或 Broker，Java E2E Job 复用
  `middleware` 中已有的持久化 RocketMQ。
- `mq-resilience-test` 不再部署 RabbitMQ 或 MySQL；RabbitMQ 迁入 `middleware`
  并使用新的 PVC，MySQL 复用 `middleware/mysql` 中的独立 `mqresilience` 数据库。
- 旧测试 MySQL 的 `mqresilience.processed_messages` 已导入共享 MySQL，迁移后和
  回归后均验证为 7 条记录。

两个测试 namespace 均保留，但只包含客户端 Job、ConfigMap、Secret 和已完成 Pod，
不再持续消耗中间件 Pod 或旧 MySQL PVC。

## 迁移后的资源边界

| 服务 | 实际运行位置 | 持久化 | 测试访问方式 |
| --- | --- | --- | --- |
| RocketMQ NameServer / Broker | `middleware`，既有 NameServer Deployment 和 Broker StatefulSet | Broker PVC `broker-store-rocketmq-broker-0`，20Gi | `rocketmq-namesrv.middleware.svc.cluster.local:9876` |
| RabbitMQ 3.13 | `middleware/rabbitmq` Deployment | 新增 `rabbitmq-data` PVC，5Gi，RWO，`local-path` | `rabbitmq.middleware.svc.cluster.local:5672` |
| MySQL 8.0 | `middleware/mysql`，既有 Deployment | 既有 `mysql-pvc`，100Gi | `mysql.middleware.svc.cluster.local:3306`，仅使用 `mqresilience` 数据库 |
| RocketMQ Java E2E | `rocketmq-resilience-test` | 无中间件卷 | 10 条生产和消费校验 |
| RabbitMQ/MySQL 韧性 Job | `mq-resilience-test` | Job 临时工作目录 | 跨 namespace Service FQDN |

所有本次 PVC 均为 `ReadWriteOnce`。集群 `local-path` StorageClass 使用节点本地
存储，因此本报告证明的是同节点卷挂载与功能连通性，不是跨节点高可用或灾备能力。

## 数据迁移说明

1. 从旧 `mq-resilience-test/mysql` 导出 `mqresilience` 数据库并导入
   `middleware/mysql`。
2. 在共享 MySQL 中创建或更新仅授权 `mqresilience.*` 的测试应用账号，并执行
   `schema.sql` 确认表结构存在。
3. 导入后执行共享 MySQL 计数校验，`processed_messages` 为 7；随后完成回归后再次
   校验仍为 7。
4. 旧测试 RabbitMQ 与 RocketMQ 都没有 PVC。它们是已完成 E2E 夹具，未承载可迁移的
   持久化业务数据；旧 RabbitMQ 队列内容不构成迁移保证。迁移后使用新的持久化
   RabbitMQ PVC，旧测试 Deployment、Service 和 2Gi MySQL PVC 已释放。

## 回归结果

| 用例 | 结果 | 证据 |
| --- | --- | --- |
| RocketMQ 跨 namespace E2E | 通过 | `rocketmq-java-e2e` Job `Complete`，耗时 3 分 31 秒；输出 `RocketMQ Java end-to-end verification passed: 10 messages consumed` |
| RabbitMQ 正常路径 | 通过 | 生产 3 条并经共享 MySQL 落库 |
| MySQL 不可达补偿 | 通过 | Job 内将 `MYSQL_HOST` 指向不可解析地址，2 条消息写入 `pending_db.jsonl`；恢复真实 FQDN 后全部补偿落库 |
| RabbitMQ 不可达补偿 | 通过 | Job 内将 `RABBITMQ_HOST` 指向不可解析地址，2 条消息写入 `outbox.jsonl`；恢复真实 FQDN 后全部重放并落库 |
| 最终校验 | 通过 | 输出 `verification passed: 7 records persisted; recovery stores are empty` |
| 旧测试中间件释放 | 通过 | 两个测试 namespace 均无 Deployment、Service 或 PVC；共享 RabbitMQ/MySQL/RocketMQ 均为 Ready |

为避免影响公共服务，RabbitMQ/MySQL 故障用客户端连接故障注入模拟，没有缩容、重启或
删除 `middleware` 中任何共享 Deployment、StatefulSet 或 PVC。这验证了客户端本地
恢复逻辑，但不替代共享中间件本身的真实故障切换演练。

## 保留现场与重跑

保留资源：

- `middleware`：共享 RabbitMQ、MySQL、RocketMQ、三个相关 PVC 和测试专用
  `mq-resilience-credentials` Secret。
- `rocketmq-resilience-test`：已完成 `rocketmq-java-e2e` Job。
- `mq-resilience-test`：已完成 `resilience-test` Job、测试应用 ConfigMap 与测试凭据。

重跑 RocketMQ 测试只重建测试 namespace：

```bash
cd k8s/rocketmq
RESET=true bash ./run-k3s-test.sh
```

重跑 RabbitMQ/MySQL 客户端恢复测试同样只重建测试 namespace：

```bash
cd rabbitmq/k8s
RESET=true bash ./run-k3s-test.sh
```

首次从旧测试 MySQL 迁移时使用：

```bash
MIGRATE_LEGACY_DATA=true REMOVE_LEGACY_TEST_MIDDLEWARE=true bash ./run-k3s-test.sh
```

## 限制

- RabbitMQ 为单副本 Deployment；RocketMQ 与 MySQL 也是现有的单副本共享服务。
- `local-path` 为节点本地存储，节点故障、跨节点迁移、备份恢复、多副本 quorum 和跨集群
  灾备均未在本次测试中覆盖。
- 共享资源的故障演练必须在维护窗口和独立故障注入设计下进行，不能由测试脚本直接缩容。
