# 新手指南：本仓库到底是干嘛的？

> 面向第一次接触本仓库的人。读完这一篇，你就能明白「仓库里这些代码在解决什么问题」以及「我该从哪里下手」。

---

## 1. 一句话总结

这是一个 **消息队列（MQ）容灾演练** 的练习仓库：用各种代码把「消息积压」「MQ 挂了」「数据库挂了」「MQ 和数据库一起挂了」这几种故障模拟出来，并演示 **怎么扛住、怎么恢复**。

换句话说，它不是要做一个生产级的 MQ 系统，而是教你 **当 MQ 出事时，应用层该怎么应对**。

---

## 2. 先补点背景：什么是消息队列（MQ）？

如果你已经懂 MQ，可以跳过这一节。

想象一个餐厅：
- **厨师（生产者）** 不断做好菜。
- **服务员（消费者）** 把菜端给客人。
- **出菜窗口（MQ / 消息队列）** 是厨师和服务员之间的「中转台」。

厨师不用等服务员有空才炒菜，直接把菜放窗口；服务员也不用围在厨师旁边，有空了就去窗口拿。这样两头解耦，效率更高。

在软件里，「菜」就是 **消息**（一条数据、一个任务、一个通知）。生产者发消息，消费者收消息，MQ 负责暂存和转发。

那问题来了：
- 厨师炒得太快，窗口堆满了 —— **消息积压**。
- 出菜窗口塌了 —— **MQ 挂了**。
- 服务员要把菜登记到台账（数据库），台账烧了 —— **数据库（MySQL）挂了**。
- 窗口塌了 + 台账烧了 —— **双双挂掉**。

本仓库就是用代码把上面这些「出事」的场景演一遍，并给出应对套路。

---

## 3. 仓库要解决的四类故障场景

| 场景 | 发生了什么 | 仓库演示的应对思路 |
| --- | --- | --- |
| **消息积压** | 生产快、消费慢，队列堆满 | 加消费者、优先关键消息、非关键消息降级丢弃、批量处理 |
| **MQ 挂掉** | 消息发不出去/收不到 | 生产者本地暂存，MQ 恢复后重发（本地消息表 / outbox） |
| **MySQL 挂掉** | 消费后要落库，但库连不上 | 消费失败重试，未落库的消息暂存本地，恢复后补偿 |
| **双双挂掉** | 最严重 | 全面降级，本地持久化一切数据，恢复后逐服务回放 |

核心套路就三板斧：**本地暂存（不丢数据）+ 重试 + 恢复后回放**。

## 5. 这些代码到底做了什么？（通俗版）

### 5.1 `cpp/` —— 用 C++ 演示「应对思路」

这些代码 **不连接任何真实 MQ**，而是用内存里的 `std::queue` 假装有一个队列，重点演示逻辑：

- **`producer.cpp`**：模拟生产者。MQ 连不上时，消息先存到本地（`storeLocally`），等恢复再 `flushLocalMessages` 重发。
- **`consumer.cpp`**：模拟消费者。消息带 `fail_` 前缀就失败 → 重试 3 次 → 仍失败进 **死信队列**；还模拟 MySQL 偶发连不上。
- **`handler.cpp`**：模拟故障处理中枢。分别演示 MQ 故障、MySQL 故障、双故障的「告警 → 检查 → 自动恢复 → 降级 → 回放」五步走。

> 给新手：想快速看懂「容灾套路」长什么样，先读这三个文件，编译跑一下看打印输出最直观。

### 5.2 `java/` —— 真连 RocketMQ 的端到端测试

这里用阿里开源的 **RocketMQ**（一个真实 MQ 中间件）来做真实收发：
- `MQProducer.java` 往 `TestTopic` 发 1000 条消息；
- `MQConsumer.java` 从同一个 Topic 收消息；
- 仓库用 `scripts/` 里的脚本在 WSL 里把 RocketMQ 跑起来，再配合 `操作指南.md` 演练积压、宕机等场景。

> 给新手：这是「玩具版」和「真实版」的过渡。看不懂 RocketMQ API 没关系，先理解它和 cpp 演示的是同一套思路，只是换成了真实中间件。

### 5.3 `rabbitmq/` —— RabbitMQ 的多语言实战

另一个是主流 MQ：**RabbitMQ**。这个目录厉害在 —— **同一套演练，用三种语言都写了一遍**：
- `python/demo.py`、`java/.../DemoApp.java`、`cpp/src/demo.cpp`：不依赖服务的 **文件系统模拟**（消息落本地文件）。
- `true_producer` / `true_consumer`：连 **真实 RabbitMQ** 的版本（Python 还连 MySQL 做端到端补偿）。

关键能力：优先级队列（critical 消息先消费）、死信队列（无效消息兜底）、MQ 宕机时 `outbox.jsonl` 暂存 + 恢复后重放、MySQL 宕机时 `pending_db.jsonl` 暂存 + 幂等补偿。

### 5.4 `k8s/` —— 把 MQ 搬上 K3s 集群做隔离演练

前面的都在单机/单容器里玩。这里用 **K3s（轻量 Kubernetes）** 把 RocketMQ、Kafka、AutoMQ、Pulsar、RabbitMQ 部署成独立的中间件，再跑真实的故障演练，并记录成 `测试报告-*.md`。还包含 **跨集群部署规范**，讲 GitOps、隔离、复制与灾备。

> 给新手：这一层偏运维/平台，初学可以先跳过，等熟悉前面再说。

## 6. 新手怎么跑起来（推荐路线）

按难度从低到高：

1. **看懂思路（最快）**
   读 `cpp/src/` 下的三个文件，看代码里的 `cout` 输出，理解「本地暂存 + 重试 + 回放」。
   编译运行见 `BUILD.md` 的「C++ 项目构建」。

2. **跑通本地 RocketMQ 演练**
   按 `操作指南.md` 在 WSL 里启动 RocketMQ → 用 Java 发消息 → 制造积压/宕机 → 观察。
   编译运行见 `BUILD.md` 的「Java 项目构建」。

3. **玩 RabbitMQ 多语言演练**
   按 `rabbitmq/README.md` 装依赖、初始化 MySQL，跑 Python 的 `true_producer` / `true_consumer`，亲手 stop/start 服务看补偿效果。

4. **进阶：上 K3s 集群**
   参考 `k8s/rocketmq/README.md` 和 `k8s/streaming/README.md`，体验真实集群里的隔离与灾备。

## 7. 给新手的几条学习建议

- **先概念，后代码**：先把第 2、3 节吃透，再看代码会轻松很多。
- **cpp 是「说明书」**：它用最简单的代码讲清楚套路，不要纠结它「没连真 MQ」。
- **死信队列 / 本地消息表 / 幂等** 是三个高频词，务必搞懂——本仓库几乎所有应对都围绕它们。
- **别一上来就 k8s**：集群部署是给有容器和运维基础的人准备的。
